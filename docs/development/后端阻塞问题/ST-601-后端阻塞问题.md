# ST-601 用户端与流式对话：后端阻塞问题

## 当前结论

登录、Token 刷新和 `/api/v1/users/me` 已有后端实现；探店、历史会话、非流式回答、流式对话、推荐结果和引用链路尚不能进行真实联调。

核对基线：`origin/main@4e71fe4`。该版本后端仅注册 health、auth、users 和 merchant analytics 路由。

## 问题清单

| 优先级 | 后端问题 | 前端影响 | 当前前端处理 | 解除阻塞标准 |
| --- | --- | --- | --- | --- |
| P0 | 缺少 `POST /api/v1/auth/ws-token` | 无法取得 60 秒一次性令牌，不能安全建立 WebSocket | 已实现取 Token 和错误提示，组件测试使用 Mock | 实现一次性、短时、使用后失效的 WS Token，并覆盖过期、重放和未登录测试 |
| P0 | 缺少 `/api/v1/conversations` 及消息列表接口 | 无法创建、恢复和持久化历史会话 | 已按接口文档定义会话类型和 API Client，测试使用 Mock 数据 | 实现创建/列表/消息游标分页/删除/截断/设置接口，并保证只能访问本人会话 |
| P0 | 缺少 `GET /api/v1/ws/chat` | 增量 Markdown、停止生成、心跳、重连和服务端错误均无法真实运行 | 前端已实现状态机、ping/pong、取消、重连和重试处理 | 实现文档中的 `chat.accepted/route/delta/sources/completed/error` 事件、30 秒心跳、取消和相同 `request_id` 恢复语义 |
| P0 | 缺少 `/v1/chat/completions` | WebSocket 不可用时，非流式消息发送同样会失败 | 已实现 OpenAI 兼容请求封装 | 实现非流式与 SSE 流式协议，并通过常用 OpenAI SDK 基础调用测试 |
| P0 | 缺少 `POST /api/v1/search` | 复合条件探店和 RAG 证据检索没有真实结果 | 前端仅能展示模拟推荐、引用和无结果兜底 | 实现 BM25 + 向量混合检索、资源过滤、融合得分和稳定来源定位 |
| P1 | 推荐与兜底事件 Schema 未在接口文档中完全固定 | 前端使用的 `chat.recommendations`、`recommendations` 和 `fallback` 字段可能与后端不一致 | 前端兼容从 `chat.sources` 或独立推荐事件读取 | 在 OpenAPI/事件文档中固定商家 ID、理由、距离、价格、更新时间、来源和兜底字段 |
| P1 | 引用的原文定位和快照字段尚无可调用链路 | 引用抽屉可展示，但无法保证跳转到真实点评/Chunk 并高亮 | 已实现安全链接和高亮展示组件 | `message_sources` 持久化引用快照，返回稳定 `source_url/source_location/chunk_id`，并通过引用一致性测试 |
| P1 | 会话与消息幂等、断线恢复尚无后端证据 | 重连可能产生重复消息或丢失已生成内容 | 前端重用 `request_id` 并保留失败消息 | 数据库落实会话内序号、`request_id` 幂等和消息状态迁移，覆盖并发和断线恢复测试 |
