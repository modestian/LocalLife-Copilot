# ST-202 权限安全的混合检索：评测阻塞说明

## 当前结论

ST-202 在当前文档约定的“标准问题集 + 演示数据规模”口径下已经通过验收：相关自动化测试 49 项全部通过，独立复跑得到 Recall@5 0.95、MRR@10 0.95、P95 17.987 ms。

上述结果不能直接证明生产环境检索质量。当前评测使用合成演示语料、20 个问题和本地确定性 Embedding；在接入真实 Embedding 模型、真实业务语料和生产规模数据前，生产代表性验收仍处于阻塞状态。

核对日期：2026-07-19。

## 已确认不阻塞当前演示验收的事项

- OpenSearch 索引启用 strict mapping，向量维度由统一配置创建并在 Embedding 写入前校验。
- Chunk 使用稳定投影 ID 幂等写入，读写 alias 通过单次 alias 更新原子切换。
- BM25 与 k-NN 双路召回共享服务端强制的 tenant、knowledge base、resource scope、有效期和营业状态过滤。
- API 返回融合得分、双路原始得分、召回来源、命中解释以及低分兜底标记。
- ST-202 相关自动化测试结果为 49 passed；本机健康 OpenSearch 上的独立复验总体结果为 PASS。

## 解除生产代表性阻塞后的留档要求

1. 记录 Embedding 模型名称、版本、维度、归一化方式和索引版本。
2. 保存评测集版本、校验和、标注规则、查询数量及各类查询分布。
3. 保存 Recall@5、MRR@10、P50/P95/P99、错误率、并发度和数据规模。
4. 报告必须使用生产 `HybridSearchService.search` 链路，并明确是否包含鉴权、HTTP 和查询 Embedding 时间。
5. 失败问题进入固定回归集，调整 analyzer、权重、阈值或模型后重新执行完整评测。
