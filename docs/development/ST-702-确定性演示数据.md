# ST-702 确定性演示数据（TK-702-01）

`python -m app.cli.seed_demo_data` 为已完成 Alembic 迁移的本地演示库写入固定业务数据。脚本是幂等的：固定 ID 的记录已存在时不会重复写入，适用于清空业务数据后的重复初始化。

## 初始化

Docker Compose 首次启动会自动执行此幂等命令，并使用 `.env` 中的
`DEMO_SEED_PASSWORD`。仓库提供的值仅适用于本机开发；共享部署前必须覆盖。也可以在
当前 PowerShell 会话中临时设置后手动执行：

```powershell
$env:DEMO_SEED_PASSWORD = "由演示执行者设置的本地密码"
docker compose up -d --build api
docker compose exec -e DEMO_SEED_PASSWORD api python -m app.cli.seed_demo_data
```

## 固定资产

- 商家：清河面馆、书香咖啡馆（使用固定 UUID 作为 `merchant_id`）。
- 点评：两家商家各 6 条，覆盖正向、中性、负向、排队/网络等趋势与归因。
- 知识文档：两份 `READY` 文档、当前版本和已索引 Chunk，包含可跳转的来源元数据。
- 公共探店语料：演示知识库通过 `USER:READ` 标记为公共语料，所有已登录账号均可探店问答；角色授权仅继续约束知识库后台管理操作。
- 对话与反馈：清河面馆问答、引用和一条待审正反馈，供反馈流程复演。
- 模型：`demo-sentiment-v1`、`demo-sentiment-v2` 和 `local-extractive-rag-v1`；聊天模型在 `chat/development` 路由中活动。
- 标准问题集：[questions.json](../../backend/demo_data/questions.json)，含两条命中问题和一条无结果兜底问题。

“商家”在当前数据库规范中不是独立表，而是 `review_analyses.merchant_id`、知识 Chunk 元数据和 `resource_grants` 共同使用的 UUID 标识；初始化脚本遵循该模型，不额外创建未迁移的表。

## 修复既有聊天数据

升级自未记录聊天模型版本的旧环境时，执行以下幂等命令。它不会修改现有演示账号密码，只会登记本地聊天模型，并回填能够确定由本地聊天运行时生成且模型版本为空的助手消息：

```powershell
docker compose build api
docker compose up -d --wait --no-deps api
docker compose exec -T api python -m app.cli.seed_demo_data --repair-chat-runtime
```

无法确认生成来源的历史消息不会被自动回填；这类消息应重新生成后再提交反馈。
