# TK-703-04 存储对账与恢复演练

本任务以 MySQL 为事实源，OpenSearch 为可重建投影，Redis 为可丢失热缓存。演练包含 MySQL/OpenSearch 对账、全量索引重建、加密数据库备份与隔离恢复、Redis 丢失后 MySQL 回源。

## 对账口径

MySQL 事实集合只包含同时满足以下条件的 Chunk：知识库为 `ACTIVE` 且未删除、文档为 `READY` 且未删除、文档版本为当前版本、Chunk 未标记 `DELETED`。投影 ID 固定为 `<document_version_id>:<chunk_no>`。

对账报告识别：

- MySQL 有而 OpenSearch 没有的缺失投影；
- 同一 `document_version_id + chunk_no` 对应多个 OpenSearch `_id` 的逻辑重复；
- 无对应 MySQL 当前事实的孤儿投影；
- `content_hash` 不一致的内容漂移；
- MySQL 中不符合确定性规则的 `opensearch_document_id`。

## 全量重建安全规则

重建始终创建新索引，不清空或覆盖当前在线索引。所有 Chunk 完成 Embedding 和写入后，对新索引执行精确对账；只有对账零差异且 MySQL 投影 ID 已规范化，才原子切换读写别名。目标索引已存在、MySQL 事实集为空或对账失败时立即终止，在线别名保持不变。

重建索引名称从 API 容器当前的 `OPENSEARCH_INDEX` 配置派生，不能硬编码其他前缀。应用启动初始化只在别名尚未建立时创建初始路由；已经由安全重建切换到有数据索引的读写别名会被保留，避免重启后重新指向空的初始索引。

## 一键演练

只允许在隔离的本地或演示环境执行。Redis 演练会清空当前 Redis DB 0，包括缓存、限流和临时令牌，因此必须显式确认：

```powershell
$env:BACKUP_ENCRYPTION_PASSWORD = Read-Host "Backup encryption password"
docker compose up -d --build

.\scripts\run_tk703_recovery.ps1 -ConfirmRedisFlush

Remove-Item Env:BACKUP_ENCRYPTION_PASSWORD -ErrorAction SilentlyContinue
```

脚本执行以下步骤：

1. 使用 `mysqldump --single-transaction` 生成一致性备份，并在 MySQL 容器内通过 OpenSSL AES-256-CBC + PBKDF2 加密；明文 SQL 不落盘。
2. 将备份恢复到时间戳命名的隔离数据库，逐表执行精确 `COUNT(*)` 并与事实库比对。
3. 输出当前别名对账报告，创建新 strict-mapping 索引并全量重建，零差异后切换别名，再次对账。
4. 显式清空 Redis DB 0，选择一条具有持久消息的会话，从 MySQL 回源并验证消息 ID 和缓存回填。
5. 默认删除隔离恢复数据库和容器临时备份；加密备份、SHA-256 与 JSON/Markdown 证据保留在 `artifacts/tk-703-04/`。

如需人工复核隔离恢复库，可添加 `-KeepRestoredDatabase`。使用后只应删除脚本输出中精确记录的 `local_life_restore_drill_<timestamp>` 数据库，禁止对事实库执行 DROP。

也可在 API 容器内单独执行只读对账：

```powershell
docker compose exec api python -m app.cli.storage_recovery reconcile `
  --report /tmp/tk-703-04-reconcile.json
```
