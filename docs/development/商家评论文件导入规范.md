# 商家评论文件导入规范

## 1. 适用范围

本规范用于通过前端“文档与版本”页面批量导入商家及评论数据。导入文件会同时进入：

1. 商家业务库：创建或更新 `merchants`，幂等写入 `reviews`；
2. 知识库：创建 `documents`、`document_versions` 和 `chunks`；
3. 检索索引：生成向量并写入 OpenSearch；
4. 情感分析：为受影响商家自动提交一次全量评论分析任务；
5. 资源授权：当行内填写 `owner_username` 时，为该用户授予对应商家的 `MERCHANT:READ`。

普通知识文档仍使用原有“知识文档”模式，不会尝试创建商家。

## 2. 文件要求

- 格式：`.csv` 或 `.xlsx`；
- CSV 编码：UTF-8 或 UTF-8 with BOM；
- 一行表示一条评论；
- 同一商家的主数据可以在多行重复，但值必须一致；
- 时间使用 ISO 8601，例如 `2026-07-20T12:30:00+08:00`；
- 经度范围 `-180` 至 `180`，纬度范围 `-90` 至 `90`；
- 金额统一使用“分”，避免浮点金额误差。

## 3. 字段定义

| 字段 | 必填 | 类型/范围 | 说明 |
| --- | --- | --- | --- |
| `merchant_key` | 是 | 1–64 字符 | 来源系统内稳定的商家键；用于跨文件幂等更新，禁止复用给其他商家 |
| `merchant_name` | 是 | 1–200 字符 | 商家展示名称 |
| `category` | 是 | 1–128 字符 | 商家品类，例如“火锅”“咖啡馆” |
| `address` | 是 | 1–500 字符 | 商家地址 |
| `longitude` | 是 | 数字 | WGS84 经度 |
| `latitude` | 是 | 数字 | WGS84 纬度 |
| `review_key` | 是 | 1–64 字符 | 该商家来源系统内稳定的评论键 |
| `review_content` | 是 | 非空文本 | 评论正文 |
| `review_rating` | 是 | 0–5 | 评论评分 |
| `reviewed_at` | 是 | ISO 8601 | 评论发生时间 |
| `avg_price_cent` | 否 | 非负整数 | 商家人均价格，单位为分 |
| `merchant_rating` | 否 | 0–5 | 商家聚合评分；缺省为 `0` |
| `business_status` | 否 | 枚举 | `OPEN`、`CLOSED`、`SUSPENDED`、`UNKNOWN`；缺省为 `UNKNOWN` |
| `author_ref` | 否 | 最长128字符 | 来源系统中的脱敏作者标识 |
| `tags` | 否 | 文本 | 标签，使用半角逗号 `,` 或竖线 `|` 分隔 |
| `owner_username` | 否 | 用户名 | 当前租户内的现有用户；导入成功后获得该商家只读权限 |

## 4. 幂等与更新规则

- 商家内部 ID 由 `租户 ID + merchant_key` 确定，同一个 `merchant_key` 重复导入不会新增商家；
- 评论由 `租户 ID + merchant_key + review_key` 唯一确定，重复导入会更新正文、评分、作者、标签和时间；
- 同一文件中，同一个 `merchant_key` 的名称、品类、地址、坐标、价格、商家评分、营业状态和归属用户必须一致；
- 任一行校验失败时，商家与评论业务数据整批不写入；异步任务状态变为失败并显示原因；
- 文档索引失败时可通过任务重试恢复，业务数据重复写入仍保持幂等；
- 每次成功导入都会为受影响商家创建全量情感分析任务；
- `owner_username` 授权是增量添加，不会自动撤销该商家已有的其他授权；
- `owner_username` 对应用户还必须通过角色拥有 `MERCHANT:READ` 权限；
- 删除知识文档只删除检索投影，不会删除已经导入的商家和评论。

## 6. 前端操作

1. 进入管理端知识库的“文档与版本”页面；
2. 将上传类型切换为“商家评论数据”；
3. 选择 CSV/XLSX 文件并提交；
4. 在任务进度卡查看加载、业务入库、切分和索引状态；
5. 成功后重新获取用户信息或重新登录，新的商家授权将出现在商家模块。

“商家评论数据”导入涉及主数据和授权变更，仅具有 `MERCHANT:CREATE` 权限的平台管理员可执行。
