# 商家评论演示数据生成指南

## 概述

项目提供了一个幂等的数据种子脚本 `backend/app/cli/seed_merchant_data.py`，用于在本地数据库中批量生成商家及评论演示数据，供前端联调、API 测试和功能演示使用。

**生成内容：**

| 数据表 | 记录数 | 说明 |
| --- | --- | --- |
| `merchants` | 20 家 | 覆盖火锅、川菜、日料、咖啡、奶茶、烧烤、面馆、西餐、甜品、粤菜、海鲜、素食、小吃、韩餐、米线、串串等品类 |
| `reviews` | 400 条 | 每家商家 20 条，含评分、评论文本、时间戳 |
| `review_analyses` | 400 条 | 对应的情感分析结果（sentiment / aspect_labels / negative_reasons） |

## 前置条件

1. Docker Desktop 已启动
2. 项目环境已初始化（首次需 `Copy-Item .env.example .env`）
3. 服务已正常运行：

```powershell
docker compose up -d --wait
```

## 执行步骤

### 第一步：确保数据库迁移已执行

脚本依赖 `merchants`、`reviews`、`review_analyses` 三张表（由迁移 `20260723_0014` 创建）。正常 `docker compose up` 启动链会自动执行 `alembic upgrade head`，如果你的环境是较早版本创建的，手动补跑：

```powershell
docker compose exec api alembic upgrade head
```

### 第二步：运行数据生成脚本

```powershell
docker compose exec api python -m app.cli.seed_merchant_data
```

成功输出：

```text
Merchant demo data ready: 21 merchants, 420 reviews, 420 review analyses.
```

> 数字可能略多于 20/400，因为 `seed_demo_data`（Compose 启动链自动执行）会先插入 2 家基础商家。

### 第三步：验证数据

```powershell
# 查看商家列表
docker compose exec mysql mysql -ulocal_life -plocal_life_dev local_life --default-character-set=utf8mb4 -e "SELECT name, category, rating FROM merchants ORDER BY rating DESC;"

# 查看某商家的评论（以老灶火锅为例）
docker compose exec mysql mysql -ulocal_life -plocal_life_dev local_life --default-character-set=utf8mb4 -e "SELECT r.content, r.rating, r.reviewed_at FROM reviews r JOIN merchants m ON r.merchant_id = m.id WHERE m.name = '老灶火锅' ORDER BY r.reviewed_at;"

# 查看情感分布
docker compose exec mysql mysql -ulocal_life -plocal_life_dev local_life --default-character-set=utf8mb4 -e "SELECT sentiment, COUNT(*) as cnt FROM review_analyses GROUP BY sentiment;"
```

## 数据设计说明

### 商家差异化

每家商家定义了各自的 **优势维度**（strengths）和 **劣势维度**（weaknesses），评论文本围绕这些维度生成，确保不同商家的分析结果有区分度。

### 情感趋势

| 趋势类型 | 商家数 | 特征 |
| --- | --- | --- |
| `stable` | 12 家 | 正面评论为主（60%），少量负面 |
| `improving` | 4 家 | 早期差评多，近期好评增加 |
| `declining` | 4 家 | 早期好评多，近期差评增加 |

### 码值对齐

- `aspect_labels` 使用 21 种维度码：`taste`、`portion`、`price`、`freshness`、`appearance`、`variety`、`space`、`quiet`、`decoration`、`hygiene`、`location`、`seating`、`waiting_time`、`attitude`、`efficiency`、`parking`、`packing`、`discount`、`set_meal`、`equipment`、`overall`
- `negative_reasons` 使用 19 种原因码：`taste_bad`、`taste_unbalanced`、`cold_food`、`too_small`、`stale`、`spoiled`、`overpriced`、`false_discount`、`dirty`、`loud`、`no_seat`、`slow_wait`、`rude_staff`、`wrong_order`、`no_parking`、`bad_pack`、`equipment_broken`、`close_early`、`delivery_delay`

以上码值与 `recommendation_generator.py` 和 `reply_generator.py` 完全一致，可直接触发经营建议和回复生成功能。

### 时间分布

评论日期分布在 **2026-04-01 至 2026-06-30**（共 3 个月），每家 20 条均匀散布。

## 幂等性

脚本使用固定 UUID（前缀 `70200000-...`），重复执行 **不会** 产生重复数据。如需清除后重新生成：

```powershell
docker compose exec mysql mysql -ulocal_life -plocal_life_dev local_life -e "DELETE FROM review_analyses WHERE model_version = 'demo-sentiment-v2'; DELETE FROM reviews WHERE source_type = 'DEMO'; DELETE FROM merchants WHERE id >= UNHEX('40000000702000008000000000000202');"
```

然后重新执行第二步即可。

## 常见问题

| 问题 | 原因 | 解决 |
| --- | --- | --- |
| `No module named app.cli.seed_merchant_data` | 容器镜像未包含新文件 | `docker compose build api` 后重新 `up -d --wait api` |
| `Table 'local_life.merchants' doesn't exist` | 迁移未执行 | `docker compose exec api alembic upgrade head` |
| `Can't connect to MySQL server` | Docker 未启动或服务未就绪 | `docker compose up -d --wait` |
| MySQL 终端内中文查询无结果 | Docker exec 交互终端无法输入中文 | 使用 `docker compose exec mysql mysql ... -e "SQL"` 方式传入中文，或用 `UNHEX(id)` 查询 |
