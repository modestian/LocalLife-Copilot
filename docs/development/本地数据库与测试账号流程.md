# 本地数据库与测试账号

本文说明如何连接 Docker Compose 中的 MySQL、检查本地数据，以及创建可供前端登录的开发测试账号。以下操作只适用于本地开发环境。

## 启动服务

首次启动或后端代码更新后，在仓库根目录执行：

```powershell
docker compose up --build --wait
```

确认服务状态：

```powershell
docker compose ps
```

浏览器统一入口为 `http://localhost:3000`，API 调试入口为 `http://localhost:18000`。

## 连接 MySQL

本地 Compose 会自动加载 `compose.override.yaml`，并仅在 `127.0.0.1` 暴露 MySQL。默认连接参数如下：

| 参数 | 默认值 | 配置来源 |
| --- | --- | --- |
| Host | `127.0.0.1` | `compose.override.yaml` |
| Port | `13306` | `.env` 中的 `MYSQL_PORT` |
| Database | `local_life` | `.env` 中的 `MYSQL_DATABASE` |
| User | `local_life` | `.env` 中的 `MYSQL_USER` |
| Password | `local_life_dev` | `.env` 中的 `MYSQL_PASSWORD` |

如果 `.env` 修改过以上变量，以 `.env` 的实际值为准。不要把本地 `.env` 或真实密码提交到 Git。

### 使用容器内命令行

无需在电脑上安装 MySQL 客户端：

```powershell
docker compose exec mysql mysql -u local_life -p local_life
```

出现 `Enter password:` 后输入 `.env` 中的 `MYSQL_PASSWORD`。输入密码时终端不显示字符属于正常现象。

进入 MySQL 后可执行：

```sql
SHOW TABLES;

SELECT
    BIN_TO_UUID(id, 1) AS id,
    username,
    display_name,
    status,
    created_at
FROM users;
```

输入 `exit` 退出 MySQL。

### 使用 DBeaver 或 DataGrip

新建 MySQL 连接并填写上表参数。驱动属性保持 MySQL 8 默认值即可。建议使用普通应用用户 `local_life`，不要日常使用 root 用户。

## 创建前端测试账号

项目没有开放注册接口，也不会在迁移中写入默认密码。请使用开发 CLI 创建账号；不要直接向 `users` 表写入明文密码或自行拼接密码哈希。

先确保后端镜像包含最新代码：

```powershell
docker compose up -d --build api
```

创建普通用户账号：

```powershell
docker compose exec api python -m app.cli.create_test_user `
  --username frontend-test `
  --display-name "前端测试用户" `
  --role USER
```

命令会交互式要求输入并确认密码，密码不会显示，也不会进入 PowerShell 命令历史。创建成功后，同一命令可以重复执行；已有用户会被恢复为启用状态并更新密码，不会生成重复用户。

可选角色包括：

| 角色 | 前端工作台 |
| --- | --- |
| `USER` | 普通用户工作台 `/app` |
| `PLATFORM_ADMIN` | 管理工作台 `/admin` |
| `KB_ADMIN` | 管理工作台 `/admin` |
| `OPS_ADMIN` | 管理工作台 `/admin` |
| `MODEL_ADMIN` | 管理工作台 `/admin` |
| `MERCHANT_ADMIN` | 商家工作台 `/merchant` |
| `MERCHANT_OPERATOR` | 商家工作台 `/merchant` |

CLI 会创建缺失的角色并为用户绑定角色，但不会自行创建业务资源授权。默认 Compose seed
已向 `USER`、`MERCHANT_ADMIN` 和 `PLATFORM_ADMIN` 角色授予演示知识库只读范围，因此这些
角色的本地测试账号可直接探店问答；访问其他知识库、商家或区域数据仍需相应授权记录。

## 验证登录

打开 `http://localhost:3000/login`，输入刚创建的用户名和密码。也可以通过 PowerShell 验证登录接口：

```powershell
$body = @{
  username = "frontend-test"
  password = "刚才设置的密码"
} | ConvertTo-Json

Invoke-RestMethod `
  -Method Post `
  -Uri "http://localhost:18000/api/v1/auth/login" `
  -ContentType "application/json" `
  -Body $body
```

响应中出现 `access_token` 和 `refresh_token` 表示登录成功。不要把令牌粘贴到文档、Issue 或聊天记录中。

## 常见问题

### `No such service` 或容器未运行

先执行：

```powershell
docker compose up -d --build
docker compose ps
```

### `Access denied for user`

检查 `.env` 中的 `MYSQL_USER`、`MYSQL_PASSWORD` 和 `MYSQL_DATABASE`。如果数据库卷是在修改密码前创建的，MySQL 不会自动修改卷内已有账号密码；开发数据不需要保留时可按《本地开发与 CI》的重置说明重新创建卷。

### CLI 报表不存在

说明迁移尚未完成。检查 `docker compose ps -a` 中的 `migrate` 状态，并查看日志：

```powershell
docker compose logs migrate
```

### 能登录但没有业务数据

账号数据和知识库数据相互独立。当前业务数据是否存在取决于相应的数据迁移、导入任务和 OpenSearch 投影；创建测试账号不会自动生成商家、点评或知识库内容。
