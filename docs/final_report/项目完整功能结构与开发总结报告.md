## 一、项目完整功能与结构（分模块）

### 1.1 项目概述

**LocalLife Copilot** 是一个面向本地生活场景的 RAG（Retrieval-Augmented Generation）智能助手系统。系统以探店推荐为核心能力，支持用户通过自然语言多轮对话，按距离、预算、菜系、场景、人数、营业状态等多维度约束寻找商家，同时提供商家口碑分析、情感洞察、竞品对比、知识库管理、模型训练与发布等完整的平台化能力。

**技术栈总览：**

| 层级 | 技术选型 |
| --- | --- |
| 前端 | Vue 3 + TypeScript + Vite + Pinia + Vue Router + Axios + Element Plus |
| 后端主服务 | FastAPI（REST / SSE / WebSocket）+ Uvicorn |
| RAG 编排 | LangChain（ChatPromptTemplate + ChatOpenAI） + LangGraph（StateGraph 对话状态机） |
| 异步任务 | Celery（Redis 消息代理） |
| 关系数据库 | MySQL 8.4 + SQLAlchemy 2.0 + asyncmy/pymysql + Alembic 迁移 |
| 缓存与会话 | Redis 7.4 |
| 搜索引擎 | OpenSearch 3.7（BM25 + kNN 混合检索，opensearch-py SDK，ik_smart / ik_max_word 分词） |
| 认证安全 | Argon2id 密码哈希 + PyJWT 令牌签发 |
| 意图路由 | 纯规则匹配（300+ 关键词 + 正则启发式，不依赖 BERT） |
| 语义嵌入 | sentence-transformers + BAAI/bge-small-zh-v1.5（512 维） |
| 情感分类 | BertForSequenceClassification（本地训练，通过 model-gateway 调用） |
| RAG 文本生成 | 阿里百炼（通过 LangChain ChatOpenAI 适配器调用） |
| ETL 处理 | pandas + pypdf + python-docx + openpyxl |
| 模型训练 | Transformers + PEFT（LoRA/QLoRA） + scikit-learn + accelerate + datasets |
| 容器编排 | Docker Compose（13 个服务，多阶段构建：base → model → runtime） |
| 反向代理 | Nginx（统一 REST / SSE / WebSocket 入口，禁用缓存/缓冲） |
| CI/CD | GitHub Actions + Git Hooks（ruff + ESLint + pytest + Vitest + Playwright E2E） |
| 可观测性 | Python logging（JSON 结构化日志，含 request_id/user_id/conversation_id/latency_ms） |

### 1.2 系统架构总览

#### 1.2.1 RAG 对话流水线

```
用户输入
    |
    v
+-----------------------------+
|  Input Guard（内容安全过滤）   |
+-----------------------------+
    |
    v
+-----------------------------+
|  Intent Router（意图路由）     |
|  knowledge_query / tool_use  |
|  / general_chat              |
+-----------------------------+
    |  (knowledge_query)
    v
+-----------------------------+
|  Constraint Extractor        |
|  距离/预算/菜系/场景/人数/     |
|  营业状态                      |
+-----------------------------+
    |
    v
+-----------------------------+
|  Clarification Planner       |
|  缺预算/人数时追问            |
+-----------------------------+
    |
    v
+-----------------------------+
|  Hybrid Retrieve             |
|  OpenSearch BM25 + kNN       |
|  双路召回 + 权限过滤          |
+-----------------------------+
    |
    v
+-----------------------------+
|  LangChain RAG Generator     |
|  百炼 LLM (qwen-plus)        |
|  基于检索资料生成回答         |
+-----------------------------+
    |
    v
+-----------------------------+
|  Output Guard（内容安全过滤）  |
+-----------------------------+
    |
    v
  答案
```

**关键说明：** RAG 生成使用 `SimpleRAGGenerator`（[langchain_rag.py](file://backend/app/agents/langchain_rag.py)），基于 LangChain + ChatOpenAI（百炼平台）的轻量管道。将检索到的 Chunk 格式化为上下文字符串，通过 System Prompt + User Prompt 调用百炼 qwen-plus 模型生成回答。LLM 不可用时自动 fallback 到原始检索结果渲染。`generation.py` 中的 `GroundedRAGGenerator` 为遗留代码，不再被实际链路使用。

#### 1.2.2 容器编排架构

```
nginx（统一入口 :3000）
  ├─ frontend（Vue 3 静态站点）
  └─ api（FastAPI :8000）
       ├─ mysql（:3306）
       ├─ redis（:6379）
       ├─ opensearch（:9200）
       └─ model-gateway（:8001）

常驻服务：worker（Celery，异步摄取/训练）
```

##### 关键实现细节

**意图路由（IntentRouter）** 采用纯规则匹配：
- `_KNOWLEDGE_MARKERS`：含 "推荐"、"探店"、"想吃"、"附近" 等 300+ 关键词
- `_TOOL_MARKERS`：识别工具调用意图
- 启发式正则：`(?:想吃|想喝|想买|想找|想去|找找)` 等动词 + 宾语组合
- 回退到 `GENERAL_CHAT`

**约束提取（ConstraintExtractor）** 同样使用纯规则：
- 距离：正则 `(\d+)公里|千米`，含 "附近" 默认 3000m
- 预算：`人均\d+元`、`¥\d+` 等模式
- 菜系/氛围/场景：预定义 alias 表（含餐饮、购物、服务 200+ 类别）
- 人数：中文数字 + 正则
- 营业状态：`现在营业|开门`

**ClarificationPlanner**：当 KNOWLEDGE_QUERY 无任何约束时，追问预算和人数。

**对话记忆**：采用 "不可变消息历史 + MySQL 持久摘要 + Redis 热缓存 + 当前分支指针" 方案，截断后不影响旧历史。

**RAG 生成流程（SimpleRAGGenerator）**：
1. Chunk 格式化：`chunks_to_context()` 将检索到的 Chunk 转为 LLM Prompt 中的结构化上下文
2. LLM 调用：LangChain `ChatPromptTemplate` → `ChatOpenAI` → `StrOutputParser`，使用 `_SYSTEM_PROMPT`（"只基于商家资料回答"）+ `_USER_PROMPT`（含 `{history}`、`{query}`、`{context}`）
3. 降级兜底：LLM 不可用时 `render_fallback()` 直接从检索结果渲染商家卡片
4. 引用生成：`chunks_to_citations()` 从 Chunk 元数据构建 `SourceCitation`（含 chunk_id、source_location、content_snapshot）

**通用对话（generate_general）**：独立 `_GENERAL_SYSTEM_PROMPT`（含领域作用域守卫），不注入检索结果。

## 三、项目开发总结报告

### 3.1 项目背景与目标

LocalLife Copilot 是为本地生活场景打造的 RAG 智能助手，旨在解决用户在餐饮、购物、休闲等场景下的探店决策痛点。项目采用 3 个 Sprint（12 天），4 名开发者协作完成 7 个 Epic、18 个 Story、60+ 个 Task，交付了 1084 个通过的测试用例、13 个容器服务的完整平台。

**核心目标：**
- 多轮约束对话：理解距离、预算、菜系、场景等 7 个维度的用户约束
- 证据可追溯：每句推荐附引用，可定位到商家、文档或点评原文
- 流式实时响应：SSE / WebSocket 双协议支持，首包 ≤ 2 秒
- 完整闭环：从知识摄入 → 混合检索 → RAG 生成 → 反馈 → LoRA 训练 → 评测 → 灰度发布

### 3.4 技术挑战与解决方案

#### 挑战 1：意图路由的领域边界
**问题**：用户可能输入完全无关的内容（如"成都天府机场"），意图路由无相关关键词但 LLM 可能在 General Chat 路径中自由回答。
**解决**：在 `_GENERAL_SYSTEM_PROMPT` 中增加领域作用域守卫，明确 LLM 仅回答本地生活相关问题，对无关话题礼貌拒绝并引导。

#### 挑战 2：多轮约束累积的正确性
**问题**：约束模型分为会话级场景和轮次级数值约束，早期实现中前端误注入 `[探店条件]` 文本块导致历史约束被二次解析。
**解决**：后端清理前端注入的文本块；`merge_constraints` 严格按"同类覆盖、异类累积"规则执行，并通过固定评测集验证。

#### 挑战 3：General Chat 兜底提示异常
**问题**：General Chat 返回 `fallback_reason="general_chat"` 导致 `is_fallback=True`，前端误渲染推荐兜底 UI。
**解决**：在 WebSocket 事件出口层增加 Intent 拦截，`intent == GENERAL_CHAT` 时跳过兜底事件发送。

#### 挑战 4：OpenSearch 权限过滤安全
**问题**：检索查询的权限过滤若可由客户端控制，存在横向越权风险。
**解决**：过滤参数在服务端 `RetrievalScope` 中根据 Token/Principal 构建，客户端参数仅用于查询意图，不参与权限决策。

#### 挑战 5：LoRA 训练可复现性
**问题**：训练环境差异可能导致结果不可复现。
**解决**：锁定基础模型 revision、数据集 hash、随机种子和超参数；支持 CPU smoke test 验证代码正确性；产物保存完整配置 + SHA-256。

### 3.6 架构设计亮点

2. **纯规则意图路由**：零模型推理延迟，100% 可解释、可调试
3. **引用可追溯**：`chunks_to_citations()` 从 Chunk 元数据构建 SourceCitation，含 chunk_id、source_location、content_snapshot

6. **容器最小权限**：所有容器 read_only、no-new-privileges，双网络隔离
7. **多阶段 Docker 构建**：base → model → runtime，按需分层
