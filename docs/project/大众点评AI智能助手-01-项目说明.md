# 大众点评 AI 智能助手项目说明

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 项目名称 | 大众点评 AI 智能助手 |
| 项目代号 | LocalLife Copilot |
| 产品形态 | 面向用户、商家与平台运营方的本地生活 AI 应用 |
| 核心范围 | 以校园或社区周边 3 公里生活圈为首期服务范围 |
| 核心技术 | Python、FastAPI、LangChain、LangGraph、OpenSearch、MySQL、Redis、Vue 3、Docker、Transformer、PEFT/LoRA |
| 文档版本 | v1.0 |

## 2. 项目背景

本地生活平台沉淀了大量商家资料、菜单、营业信息和用户点评，但传统筛选和关键词搜索难以理解“适合写作业的安静咖啡馆”“下雨天想吃热乎且人均 50 元以内”等复合意图。用户需要在大量评价中自行归纳，商家也难以从碎片化反馈中快速定位经营问题。

本项目建设一个围绕“用户—商家—平台”三方协作的 AI 智能助手：用户通过自然语言完成搜店和场景推荐；商家获得情感分析、差评归因、亮点挖掘和回复建议；平台通过知识库、内容审核、运行监控与反馈闭环持续提升数据和模型质量。

## 3. 建设目标

1. 提供支持多轮上下文、流式输出和可信引用的对话式探店体验。
2. 建设多源数据接入、清洗、切分、向量化和混合索引的一体化知识库。
3. 基于 OpenSearch 实现 BM25 关键词检索、向量语义检索和重排融合。
4. 为商家提供可解释的口碑分析、竞品对比、评价回复和经营建议。
5. 建立用户反馈、微调数据集生成、Transformer LoRA 训练、评测和模型发布闭环。
6. 采用 Docker Compose 构建可复现、可演示、可扩展的部署环境。

## 4. 用户与价值

| 角色 | 主要诉求 | 平台价值 |
| --- | --- | --- |
| 普通用户 | 快速找到符合场景、预算和距离的商家 | 对话推荐、语义搜店、评价摘要、来源溯源 |
| 商家用户 | 理解口碑变化并降低运营成本 | 情感趋势、差评归因、竞品对比、辅助回复 |
| 区域运营 | 维护内容质量并发现区域热点 | 热词热榜、违规审核、刷单预警、热点洞察 |
| 平台管理员 | 管理知识、模型、权限和系统运行 | RBAC、知识库、模型配置、审计与监控 |
| 开发/算法人员 | 快速迭代 AI 能力 | OpenAI 兼容 API、工具注册、评测集、LoRA 流水线 |

## 5. 产品范围

### 5.1 首期必须交付（MVP）

- 用户注册登录与 RBAC 权限校验。
- 商家、菜单、点评等演示数据导入与知识库管理。
- 文档上传、解析、清洗、切分、索引、删除和状态追踪。
- BM25 + 向量混合检索，支持商家、距离、价格、菜系、营业状态等过滤。
- OpenAI Chat Completions 兼容接口及 WebSocket 流式对话。
- 多轮会话、场景推荐、口碑摘要、答案引用和无结果兜底。
- 评价情感分析、关键词提取、差评归因和基础趋势图表。
- 用户反馈接口、JSONL 数据集导出、至少一次 LoRA 微调与前后评测。
- Vue 3 用户端与管理端核心页面、Docker Compose 一键启动。
- Swagger/OpenAPI、日志、测试和演示数据。

### 5.2 应完成（增强版）

- 商家竞品对比、评价回复建议、经营建议。
- 提示词版本管理、知识库多版本、会话回滚。
- 内容审核工作台、敏感词规则、区域热词与热榜。
- Redis 会话持久化、异步任务进度和运行看板。
- LangGraph 智能路由与可配置工具注册。

### 5.3 可选扩展

- 图片 OCR、语音 ASR、多模态问答。
- 疑似刷单异常检测、敏感事件预警。
- Pandas Agent 沙箱分析工具。
- Confluence、Git、网页等更多在线数据源。

## 6. 技术栈

| 层次 | 选型 | 用途 |
| --- | --- | --- |
| 前端 | Vue 3、TypeScript、Vite、Pinia、Vue Router、Element Plus、ECharts | 用户端、商家端和管理端 |
| API | Python 3.12.0、FastAPI、Pydantic v2、SQLAlchemy 2、Alembic | REST/WebSocket API、校验、ORM、迁移 |
| AI 编排 | LangChain、LangGraph | RAG 链、路由、工具调用、状态工作流 |
| 搜索 | OpenSearch | BM25、k-NN 向量、过滤、聚合、混合检索 |
| 数据 | MySQL 8、Redis | 事务元数据、用户权限、反馈；缓存、会话、任务进度 |
| 模型 | Hugging Face Transformers、sentence-transformers、PEFT、TRL | Embedding、分类、生成、LoRA 微调与评测 |
| 异步任务 | Celery/RQ（项目统一选择其一，推荐 Celery） | 文档解析、索引、批量分析、训练任务调度 |
| 运维 | Docker、Docker Compose、Nginx、Prometheus/Grafana（可选） | 环境隔离、服务编排、网关和监控 |
| 测试 | Pytest、Vitest、Playwright、Locust | 单元、组件、端到端和性能测试 |

## 7. 系统能力边界

- 推荐依据仅来自用户有权访问且处于有效状态的数据，不抓取或展示无授权的个人隐私信息。
- AI 输出是辅助建议，不承诺商家实际库存、排队时间或营业状态；界面必须显示数据更新时间。
- 引用不足或检索得分低于阈值时必须触发兜底，禁止编造商家、价格和评价。
- LoRA 训练只使用获得授权、已脱敏且通过质量筛选的数据；模型发布前必须通过离线评测和人工抽检。
- LLM 生成代码不得直接在主服务执行；如实现 Pandas Agent，必须使用无网络、只读输入、限时限资源的独立沙箱容器。

## 8. 总体里程碑

| 阶段 | 目标 | 核心产物 |
| --- | --- | --- |
| M1 基础工程 | 跑通前后端、数据库和权限 | Compose、登录、RBAC、数据库迁移 |
| M2 数据与检索 | 跑通数据入库和混合检索 | ETL、OpenSearch 索引、检索评测 |
| M3 智能对话 | 完成可溯源的多轮推荐 | RAG、WebSocket、对话 UI、引用跳转 |
| M4 商家与运营 | 完成口碑分析和后台 | 情感分析、趋势图、内容管理 |
| M5 微调闭环 | 完成 LoRA 训练和模型切换 | JSONL、LoRA Adapter、评测报告 |
| M6 质量交付 | 完成测试、监控和答辩材料 | 测试报告、API 文档、演示脚本 |

## 9. 成功指标

- Top-5 商家检索命中率不低于 80%（基于项目标准问题集）。
- 有引用回答占比 100%，引用可跳转且原文一致率 100%。
- P95 API 响应时间（不含 LLM 首字等待和生成时间）低于 500 ms。
- 流式回答首包时间在演示环境中不高于 2 秒。
- 情感三分类宏平均 F1 不低于 0.80；LoRA 微调后不得低于基线，目标提升至少 3 个百分点。
- 核心后端业务单元测试覆盖率不低于 70%。
- 高优先级用户故事全部通过验收，无阻断级安全缺陷。
