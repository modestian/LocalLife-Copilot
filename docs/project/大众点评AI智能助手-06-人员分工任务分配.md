# 大众点评 AI 智能助手：史诗、故事、任务与人员分工

## 1. 拆分与估算规则

本文将项目工作统一为“史诗（Epic）→故事（Story）→任务（Task）”，作为 Jira 建单、排期和验收基线。

```text
Epic：可跨 Sprint 的大模块
└─ Story：从单一用户/业务角色出发、可独立验收的需求
   └─ Task：产生具体代码、配置、数据、测试或文档的实施工作
```

- 一个 Story 只属于一个 Epic，且只有一个负责人；负责人对整个 Story 的验收结果负责。
- 一个 Task 只属于一个 Story，表中同时标明唯一“所属 Epic”和唯一负责人，不写“共同负责”。
- Story 预计人日等于其全部 Task 预计人日之和；`1 人日 = 8 小时`，`0.25 人日 = 2 小时`。
- Story 使用 P0～P3 优先级；Task 继承 Story 优先级。
- 接口、Schema、页面、测试和脚本属于 Task，不再作为需求故事。
- 可选的 OCR/ASR、多模态、刷单识别、Pandas Agent 和更多在线数据源只进 Backlog。

### 1.1 优先级

| 优先级 | 含义 | 排期规则 |
| --- | --- | --- |
| P0 阻断 | 核心链路、安全门禁或必选技术缺失即无法验收 | 必须完成，不以 P2 工作替代 |
| P1 高 | 主要业务价值或明确要求，缺失会显著降低完整度 | P0 稳定后优先完成 |
| P2 中 | 工程质量、运营效率或体验增强 | 容量不足时可裁剪增强验收项 |
| P3 低 | 可选探索 | 本期不占交付容量 |

### 5.1 EP-01 平台基础、数据与权限

#### ST-101 安全登录与资源范围授权

- **用户故事**：作为平台管理员，我希望用户通过安全令牌登录并按角色和资源范围访问数据，以避免横向越权。
- **负责人 / 优先级 / 预计时间**：L / P0 / 2.50 人日。
- **功能描述**：提供统一认证与授权底座，覆盖账号密码登录、访问令牌签发、刷新令牌轮换与撤销、当前用户查询，以及角色权限和知识库/商家/区域资源范围的双层校验。
- **验收准则**：① 正确账号登录返回 Access Token 与 Refresh Token，错误凭据返回 401；② 刷新后旧 Refresh Token 立即失效，退出后令牌不可再次使用；③ 密码仅以 Argon2id 或 bcrypt 哈希保存；④ 无角色权限返回 403，无资源范围的数据在接口和 Repository 查询中均不可见；⑤ /api/v1/users/me 返回用户、角色和授权范围；⑥ 401、403、刷新重放及横向越权自动化测试全部通过。

## 7. Definition of Ready / Done

### 7.1 Story Ready

- 已标注唯一 Epic、唯一负责人、优先级、预计人日、依赖和目标 Sprint。
- 用户故事描述角色、需求和价值；验收条件可由测试或演示证明。
- 全部 Task 都有唯一负责人、所属 Epic、具体交付物和独立预计人日。
- 跨模块 API、事件、Schema 或 Mock 已冻结；外部算力和模型下载方案已确认。

### 7.2 Story Done

- 全部 Task 完成，Story Owner 按验收条件签收，相关 P0/P1 缺陷关闭。
- 代码通过格式、静态检查、单元/集成测试和必要 E2E；数据库变更有 Alembic。
- OpenAPI、事件 Schema、配置样例、README 和运行命令同步更新。
- 日志无密钥和敏感数据；权限、幂等、异常、并发和回滚场景已验证。
- AI/检索/模型 Story 提交固定评测集及指标，不以主观演示代替量化证据。
