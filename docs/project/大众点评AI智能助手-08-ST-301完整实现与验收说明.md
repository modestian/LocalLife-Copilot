# ST-301 可溯源多轮 RAG 推荐实现与验收说明

## 1. 完成范围

本文记录 ST-301 及 TK-301-01～TK-301-06 的完整实现和验收证据。OpenAI 兼容接口、SSE、WebSocket 和受控工具执行属于 ST-302，不计入本故事完成范围。

## 2. 可执行工作流

系统使用 LangGraph `StateGraph` 编译以下生产拓扑：

```text
input_guard
  ├─ BLOCK → output_guard → persist
  └─ ALLOW → load_memory → route_intent
                            ├─ general_chat → generate_general
                            ├─ tool_use → tool_guard
                            └─ knowledge_query → extract_constraints
                                                   ├─ ask_question
                                                   └─ hybrid_retrieve
                                                        → generate_grounded
                                                        → output_guard
                                                        → persist
```

所有节点更新均经过 `ChatState` 白名单校验，禁止把思维链或未声明字段写入状态。用户、租户检索范围和请求信息通过每次运行的上下文注入，不进入模型 Prompt。

## 4. 关键可靠性约束

- 检索范围只能由服务端注入 `tenant_id`、知识库和资源权限范围。
- 无证据、证据数量不足、非法模型输出或不支持引用均返回明确兜底，不保存伪引用。
- 有依据的助手消息和 `message_sources` 原文快照通过同一仓储事务写入。
- 受限输入不会写入会话消息历史；只保存安全拒答和审计信息。
- `request_id` 为用户消息提供幂等键，助手消息使用稳定派生键，避免重试产生重复回答。
- truncate 不物理删除历史，但会清除摘要与派生约束，防止废弃分支事实泄漏到新分支。
