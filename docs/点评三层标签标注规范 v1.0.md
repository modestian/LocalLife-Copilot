# 第一章 通用标注总则
## 1.1 三层标签基础约束
1. 一级情感：每条点评**单选唯一**，必选；
2. 二级维度：多选，文本提及对应内容即打标，无重复；
3. 三级差评归因：仅 `sentiment=NEGATIVE` 时可填写，好评/中性必须为空数组；
4. 强绑定规则：每一条三级归因标签，必须存在对应二级维度，否则判定标注错误；
5. 标签仅使用英文编码，禁止自定义中文标签；
6. 无效文本（乱码、纯广告、无内容水评）单独归档，不参与标注与训练。

## 1.2 基础通用判定总原则
1. 仅客观陈述营业时间、价格、位置，无主观褒贬 → 中性；
2. 好评里存在轻微小瑕疵，但整体推荐、愿意复购 → 标好评，不添加差评归因；
3. 夸赞、吐槽内容各占一半，无明显偏向 → 中性；
4. 通篇抱怨、明确避雷、拒绝再来 → 差评；
5. 只拍照打卡，无任何体验评价文字 → 中性；
6. 同一段文本多次提到同一维度，标签只勾选一次，不重复。

# 第二章 一级情感标签判定规则（3种）
## 2.1 POSITIVE 好评
### 判定标准
文本整体以满意、夸赞、推荐、愿意复购为主，少量轻微缺点不改变整体正向倾向。
### 正向关键词
好吃、新鲜、分量足、服务热情、环境好看、上菜快、性价比高、下次再来、强烈推荐
### 正面样例
原文：这家家常菜味道正宗，食材新鲜，服务员很贴心，下次还会来
标注：sentiment=POSITIVE，aspect_labels=["taste","freshness","attitude"], negative_reason=[]
### 反面反例（不能标好评）
原文：味道还行，但全程没人搭理，上菜等一小时，再也不来
说明：核心体验严重拉垮，明确排斥，应标NEGATIVE

## 2.2 NEUTRAL 中性
### 判定标准
分三类：纯客观信息；无褒贬平淡体验；好坏对半无偏向。
### 样例1（纯客观）
原文：门店9点营业，双人套餐75，地铁口步行3分钟
标注：sentiment=NEUTRAL，aspect_labels=["set_meal","location"], negative_reason=[]
### 样例2（平淡无褒贬）
原文：口味普通，环境正常，没有特别出彩的地方
标注：sentiment=NEUTRAL，aspect_labels=["taste","decoration"], negative_reason=[]
### 样例3（好坏平衡）
原文：菜品好吃，但是店内特别吵，有利有弊
标注：sentiment=NEUTRAL，aspect_labels=["taste","quiet"], negative_reason=[]
### 反面反例（不能标中性）
原文：味道极差，食材发臭，千万别来
说明：强烈负面，标NEGATIVE

## 2.3 NEGATIVE 差评
### 判定标准
整体存在明显不满，出现避雷、难吃、脏乱、态度差、不会再来等负面表达，核心体验存在缺陷。
### 负面关键词
难吃、变质、凉透、分量少、态度恶劣、脏乱、等待过久、配送超时、虚假优惠
### 正面样例
原文：等了一小时才上菜，菜全凉，味道发苦，不会再来
标注：sentiment=NEGATIVE，aspect_labels=["waiting_time","taste"], negative_reason=["slow_wait","cold_food","taste_bad"]
### 反面反例（不能标差评）
原文：环境稍微有点吵，但菜品巨好吃，强烈推荐
说明：轻微缺点，整体推荐，标POSITIVE

## 2.4 一级标签边界模糊场景处理
| 模糊场景 | 统一处理方案 | 示例 |
| ---- | ---- | ---- |
| 轻微吐槽+结尾强烈推荐 | POSITIVE，无三级归因 | 分量一般，但味道绝了，强力安利 |
| 优缺点各一半，无整体倾向 | NEUTRAL | 菜新鲜但价格很贵，不好不坏 |
| 仅说明门店基础信息，无感受 | NEUTRAL | 人均60，门口有公共停车场 |
| 短暂排队，无不满情绪 | NEUTRAL | 饭点人多，稍微等了十分钟 |
| 明确踩雷、拒绝复购 | NEGATIVE | 食材变质，踩雷不推荐任何人来 |

# 第三章 二级评价维度标签完整判定规则（共21个）
## 3.1 菜品产品类
1. `taste` 口味
判定：描述菜品、饮品口感、咸、辣、苦、香、味道好坏均打标。
样例：奶茶很甜/菜太咸/汤底香浓 → 打taste
2. `portion` 分量
判定：描述菜量、饮品容量、食材多少、大小份。
样例：分量很小/一大盆很实在 → 打portion
3. `price` 性价比/价格
判定：提及贵、便宜、划算、不值、人均定价。
样例：价格虚高/性价比很高 → 打price
4. `freshness` 新鲜度
判定：食材新鲜、不新鲜、存放久。
样例：肉不新鲜/水果现切很新鲜 → 打freshness
5. `appearance` 卖相/颜值
判定：摆盘好看、拍照出片、外观精致。
样例：蛋糕颜值高很适合拍照 → 打appearance
6. `variety` 品类选择
判定：菜品款式多/选择少、有无忌口菜品。
样例：菜单只有十款选择很少 → 打variety

## 3.2 环境类
1. `space` 空间大小
判定：店内宽敞、拥挤、面积大小。
2. `quiet` 安静度
判定：吵闹、噪音、适合自习、安静聊天。
3. `decoration` 装修氛围
判定：装修风格、氛围感、装修好看/老旧。
4. `hygiene` 环境卫生
判定：桌面、地面、卫生间、餐具干净/油污垃圾。
5. `location` 位置交通
判定：好找、偏僻、地铁公交近。
6. `seating` 座位布局
判定：座位拥挤、靠窗、无座位、座椅舒服。

## 3.3 服务类
1. `waiting_time` 等待时长：排队、上菜、核销等待快慢
2. `attitude` 服务态度：店员热情/冷漠/不耐烦
3. `efficiency` 办事效率：结账、加菜、处理问题快慢，上错漏单
4. `parking` 停车配套：有无车位、停车收费、停车难易
5. `packing` 打包/配送：外卖包装、密封、保温、漏洒

## 3.4 活动配套类
1. `discount` 优惠活动：团购、代金券、折扣套路、限制使用
2. `set_meal` 套餐：单人/多人套餐搭配、套餐价格
3. `equipment` 店内设备：WiFi、空调、充电插座好坏

## 3.5 综合体验类
1. `overall` 整体综合感受：无细分维度，笼统评价整体好坏

## 3.6 二级标签通用边界处理
1. 一句话同时提到多个维度，全部勾选，不遗漏；
2. 仅说性价比低，同时勾选 `price`；
3. 外卖漏汤，勾选 `packing`；
4. 全文只有一句笼统评价，仅勾选 `overall`；
5. 同一维度重复描述，标签只保留一个，不重复标注。

# 第四章 三级差评归因标签判定规则（仅NEGATIVE可用，共19个）
## 绑定约束总表
| 三级归因编码 | 必须配套二级标签 |
| ---- | ---- |
| taste_bad、taste_unbalanced、cold_food | taste |
| too_small | portion |
| stale、spoiled | freshness |
| overpriced | price |
| false_discount | discount |
| dirty | hygiene |
| loud | quiet |
| no_seat | seating |
| slow_wait | waiting_time |
| rude_staff | attitude |
| wrong_order | efficiency |
| no_parking | parking |
| bad_pack、delivery_delay | packing |
| equipment_broken | equipment |
| close_early | overall |

## 4.1 菜品价格类
1. `taste_bad` 味道难吃：菜品/饮品口感糟糕、难下咽
2. `taste_unbalanced` 咸淡辣度失衡：过咸、过辣、味道不协调
3. `cold_food` 菜品变冷：上菜慢导致餐品冰凉
4. `too_small` 分量太少：菜量缩水，不够食用
5. `stale` 食材不新鲜：口感发柴、存放太久
6. `spoiled` 食材变质：发酸、发臭、发霉变质
7. `overpriced` 价格偏高：定价贵，品质不配价格
8. `false_discount` 虚假优惠：团购宣传与到店限制不符

## 4.2 环境类
1. `dirty` 店内脏乱：地面桌面油污、垃圾堆积
2. `loud` 环境嘈杂：音响吵闹、人声嘈杂无法聊天
3. `no_seat` 无座位：到店长时间无空位、排队久无座

## 4.3 服务类
1. `slow_wait` 上菜等待久：排队、出餐耗时过长
2. `rude_staff` 店员态度差：冷漠、顶嘴、不耐烦
3. `wrong_order` 上错漏单：菜品上错、少送漏送

## 4.4 配套打包类
1. `no_parking` 无停车位：无配套车位、停车不便
2. `bad_pack` 打包破损漏洒：包装破损、汤汁渗漏
3. `equipment_broken` 设备故障：WiFi断、插座/空调损坏

## 4.5 时效经营类
1. `close_early` 提前打烊：未到营业时间提前赶客
2. `delivery_delay` 配送超时：外卖远超承诺送达时间

## 4.6 三级标签边界模糊处理
1. 一条点评多个问题，对应所有三级标签全部勾选；
2. 仅笼统说体验差，无具体问题：只标overall，不添加任何三级归因；
3. 非差评文本，negative_reason强制置空；
4. 三级标签无对应二级维度，判定标注错误，打回重标。

# 第五章 全场景边界模糊案例统一处理方案
## 5.1 情感判定冲突案例
### 案例1：少量瑕疵，整体推荐
原文：分量有点少，但味道一绝，强烈推荐再来
处理：sentiment=POSITIVE，aspect_labels=["portion","taste"]，negative_reason=[]
### 案例2：好坏对半，无偏向
原文：食材新鲜，但店内音响特别吵，各有优缺点
处理：sentiment=NEUTRAL，aspect_labels=["freshness","quiet"]，negative_reason=[]
### 案例3：纯客观信息无情绪
原文：单人套餐58，门店在大学城商圈
处理：sentiment=NEUTRAL，aspect_labels=["set_meal","location"]，negative_reason=[]
### 案例4：多重负面明确避雷
原文：上菜一小时，菜变质发苦，店员态度极差，千万别来
处理：sentiment=NEGATIVE，aspect_labels=["waiting_time","freshness","taste","attitude"], negative_reason=["slow_wait","spoiled","taste_bad","rude_staff"]

## 5.2 标签绑定冲突错误样例（禁止出现）
错误标注示范：
sentiment=NEGATIVE
aspect_labels=["taste"]
negative_reason=["dirty"]
校验拦截：dirty对应二级标签hygiene，当前维度不存在，标注作废重标。

## 5.3 复合多问题差评处理案例
原文：外卖超时送达，包装破损漏汤，拿到手菜全凉很难吃
正确标注：
sentiment=NEGATIVE
aspect_labels=["packing","waiting_time","taste"]
negative_reason=["delivery_delay","bad_pack","cold_food","taste_bad"]

## 5.4 中性边界：轻微抱怨无抵触
原文：周末人比较多，需要排队十几分钟
处理：sentiment=NEUTRAL，仅标注waiting_time，无差评归因

# 第六章 标注校验规则（人工+程序双重校验）
1. 一级标签只能是 POSITIVE / NEUTRAL / NEGATIVE，其他字符非法；
2. 情感非NEGATIVE时，negative_reason必须是空数组；
3. 所有二级、三级标签必须在label_dict_v1.json枚举内，自定义标签直接拦截；
4. 每一条三级归因必须存在对应二级维度，否则标注无效；
5. 二级/三级数组内元素不可重复；
6. 文本含隐私、乱码、广告，直接归类无效样本，不进行标签标注。

# 第七章 标注流程规范（双人复核流程）
1. 单人初标：对照本规范完成每条文本三层标签标注；
2. 双人独立复核：两名标注人分开标注同一批样本；
3. 分歧汇总：两人标签不一致的文本单独提取；
4. 统一口径：对照本规范边界案例确定唯一标准，修正样本；
5. 归档记录：所有分歧案例录入本文档「边界模糊场景」章节，固化判定标准；
6. 清洗去重：删除重复文本、无效水评，统一文本标点格式。

# 第八章 版本迭代规则
1. 本文档版本v1.0，配套label_dict_v1.json、100条基准样本；
2. 新增、删除、修改任意标签，必须升级规范大版本（v1.1、v2.0）；
3. 版本更新同步修改：标签字典、样本库、JSON Schema、入库校验逻辑；
4. 旧版本标注样本，如需复用需按新版规范全量重标注。
